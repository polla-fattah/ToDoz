Architectural Manifesto

The ToDoz Philosophy: Principles of Sovereign Productivity

“Your data belongs on your devices first. Tools should be fast, deterministic, and respectful of your attention.”
Section 01

The Core Manifesto

Modern productivity software has lost its way. Mainstream tools (Notion, Todoist, Evernote, ClickUp) have converged into slow, subscription-based, cloud-locked silos burdened with unwanted generative AI summaries, tracking telemetry, and continuous feature bloat.

ToDoz was engineered on a counter-philosophy
01
Sovereignty: You own your data. It resides locally on your hardware first and foremost.
02
Speed: Local interactions must be sub-100ms and operate with zero network dependency.
03
Determinism: Recurring schedules, filters, and quick-add syntax must be mathematically predictable, not guessed by non-deterministic probabilistic models.
04
Focus: A task manager must be an elite execution engine—not an inferior text editor, a social network, or a bloated corporate project suite.
Section 02

The Five Foundational Pillars

Every design decision in ToDoz stems from these five architectural principles:

Pillar 01 SQLite • Drift

Local-First & Offline Sovereignty

The Device is Primary: Every read, write, query, and state transition occurs against a local data store (Drift SQLite). The network is strictly an optional transport layer, never a prerequisite for interaction.
Resilient to Outages: Whether in airplane mode, inside an offline server room, or during an internet blackout, the application functions identically.
Zero UI Latency: Tapping a checkbox or typing a task never displays a loading spinner or awaits a network handshake.
Pillar 02 Docker • LWW Sync

Self-Hosted, Lightweight Synchronization

Private Cloud, Not Public Silos: Synchronization is managed by a single-binary, self-hosted service with minimal operational overhead.
Zero Credential Hassle: Device pairing via short-lived, one-time invitation codes eliminates password management, email verification loops, and third-party auth dependencies.
Tailscale & VPN Ready: First-class compatibility with private mesh overlays ensures your sync server never needs to expose public open ports to the internet.
Pragmatic Merge Strategy: Field-level Last-Write-Wins (LWW) with change-capture triggers delivers 99.9% of the practical utility of complex CRDTs with a fraction of the architectural overhead.
Pillar 03 Deterministic Lexer

Deterministic Parsing Over Probabilistic AI

Rule-Based Certainty: Natural-language inputs (e.g. Review draft tomorrow at 4pm p1 #research {nov 30}) are parsed by a deterministic lexer/parser with mathematical precision.
Explicit Failure Modes: If an input or recurrence expression (every 1st wed) cannot be parsed, the system informs you why rather than silently guessing incorrectly.
Zero Telemetry & Battery Drain: Deterministic engines run entirely offline with zero battery drain, zero token costs, and zero leakage of personal schedules to external API providers.
Pillar 04 Execution vs. Reflection

The Separation of Concerns (Tasks vs. Knowledge)

Execution vs. Reflection: Tasks are operational, stateful, and ephemeral (checkboxes, alarms, snooze states, priorities). Notes and diaries are archival, relational, and reflective (prose, retrospectives, cross-linked ideas).
The Anti-Monolith Stance: Do not build a mediocre text editor inside a task manager, and do not shoehorn a fragile task engine into a markdown note tool.
Loose Coupling: Connect tools through standard operating-system protocols (URI schemes like todoz:// and obsidian://, terminal CLIs, or calendar .ics standards) rather than fusing them into a sluggish monolith.
Pillar 05 50-Year Survivability

Data Longevity & Plain Text Respect

Long-term Survivability: Any archive that matters for 10 to 50 years should exist as open SQLite databases and plain Markdown files stored directly in your local file system.
Export Freedom: Structured task data is always exportable in standard formats (CSV, ICS, JSON) with non-destructive backup safety nets.
Section 03

Replicating Across Markdown Ecosystems

How ToDoz integrates cleanly alongside a local-first daily journal or Second Brain:

1. Execution Layer (ToDoz)
Fast daily triage, alarms, priorities, calendar time-grids, and LWW device synchronization running natively on a local SQLite store.
Loose Coupling via URIs (todoz://, obsidian://) & iCal feeds
2. Knowledge & Diary Layer (Markdown Vault)
Daily journals, research thoughts, and retrospective synthesis saved in plain .md files on your local filesystem, synchronized via private Git or Syncthing.

The Daily Workflow:

  1. Local Filesystem as Single Source of Truth: Keep daily notes in Daily/YYYY-MM-DD.md.
  2. Zero SaaS Lock-In: Sync folders using Syncthing over Tailscale or automated Git push hooks.
  3. Mobile Read/Write: Point Obsidian Mobile or Markor to the synchronized folder.
  4. End-of-Day Synthesis: Review completed tasks in ToDoz, then record achievements and retrospective reflections in your daily log.
Section 04

The Engineering Evaluation Checklist

Before adding any feature to ToDoz or adopting a new productivity component, evaluate it against these five tests:

1
The Airplane Test
Does this feature work seamlessly with zero internet connection? If it requires a server handshake to render UI, it fails.
2
The 100ms Test
Can this action be executed and visually reflected in the UI in under 100 milliseconds? Tapping a checkbox must never wait.
3
The Longevity Test
If the server or application is discontinued tomorrow, is your historical data still completely readable and recoverable?
4
The Scope Test
Does this belong to action/execution (task), or reflection/synthesis (note)? If reflection, delegate it to the markdown vault.
5
The Dependency Test
Does this introduce an external API dependency or monthly SaaS liability that compromises privacy or stability? If yes, reject it.
